# 📜 Системный Манифест Разработки

> **Манифест проекта gatePass (v1.0, GPUIX-редакция).** Основан на
> универсальном ядре, фронтовые разделы адаптированы под стек проекта:
> **Frontend** — GPUIX (`@gpuix/react`): React + TypeScript, нативное
> GPU-приложение без DOM, запуск и сборка через Bun (FSD);
> **Backend** — Node.js + Express + TypeScript; **БД** — PostgreSQL (sqlite не
> используется); у проекта есть **AI-модуль**. Vite, Ant Design и Tailwind в
> проекте отсутствуют.

## 🏗️ Именование (БЭМ и Типы)

- **БЭМ-синтаксис:** `block__element-subElement`. Разделитель элемента — `__`,
  подэлемента/модификатора — один дефис `-`. Двойные дефисы (`--`) и дефисы в
  имени блока, ломающие структуру (типа `block-part__element`), категорически
  запрещены. Используй `block__part-element`.
- **Интерфейсы и Типы:** Внутри компонента: `interface IProps`, `type TState`.
  Экспортируемые (в `model.ts`): `interface I[Name]`, `type T[Name]`.

## 🛣️ Роутинг и Импорты

- **Запрет хардкода путей:** UI-пути строго через `AppRoutes`, API-пути — через
  `ApiRoutes`.
- **Публичный API:** Импорты между модулями только через алиасы
  (`@/features/auth`) и точку входа `index.ts`. Глубокие импорты запрещены.
- **Импорты ESM-пакетов:** При импорте из сторонних библиотек проверяй тип
  экспорта. Дефолтный импорт (`import X from 'pkg'`) из пакета, имеющего только
  именованные экспорты, ломает сборку — используй именованный импорт
  (`import { X } from 'pkg'`). Подпакеты GPUIX импортировать по их точкам входа
  (`@gpuix/react/select`, `@gpuix/react/tooltip`, `@gpuix/react/automation`).

## 🚨 Безопасность типов и Предотвращение ошибок (Runtime & Lifecycle)

- **Безопасность Null/Undefined:** Во избежание ошибок
  `Cannot read properties of null/undefined` при работе с асинхронными
  объектами, хуками (например, `editor?.commands`) или API-данными, всегда
  используй опциональное зацепление `?.` и дефолтные значения. Прямое обращение
  без проверки к свойствам потенциально неинициализированных объектов
  категорически запрещено.
- **Асинхронность (Запрет Promise):** Использование явного `Promise`
  (`new Promise`, `Promise.all`, возвращаемых типов `: Promise<...>`, цепочек
  `.then()` / `.catch()`) категорически запрещено на клиенте и сервере. Весь
  асинхронный код пишется строго через `async / await` и блоки `try / catch`.
  Вместо `Promise.all` использовать циклы `for...of` с `await`.

## 🛠️ Стек и Strict React Style

- **Базовый стек:** TypeScript (`.ts`, `.tsx`), GPUIX (`@gpuix/react`) с
  `jsxImportSource: "@gpuix/react"`. Нативные элементы GPUIX (`<div>`, `<text>`,
  `<input>`, `<virtual-list>`, `<anchored>`, `<img>`, `<svg>`) оборачиваются в
  компоненты `shared/ui/*`; иконки — lucide SVG из `assets/icons`, тонируются
  через `style.color`.
- **Компоненты:** Только стрелочные функции (`const MyComponent = () => {}`).
  Использование `function` запрещено.
- **Структура вывода:** Строго один `return` с JSX. Несколько `return` (для
  загрузок/ошибок) запрещены, используй тернарные операторы/условный рендеринг
  внутри единого JSX.
- **Кастомный If:** Запрещено использовать `&&` или тернарники с возвратом
  `null` для условного рендеринга. Используй `<If condition={...}>...</If>`
  (`shared/ui/If`).
- **Чистота кода:** Неиспользуемые переменные, импорты, пропсы запрещены (ошибки
  TS6133). Комментарии (`//`, `/* */`, JSDoc, JSX) полностью запрещены — код
  должен быть самодокументируемым.

## 🧰 Динамические Навыки (Skills)

- **Локальные навыки:** Перед началом выполнения любой задачи обязательно проверяй папку `.gemini/skills/`. Если задача соответствует тематике локального навыка (например, `ui-ux-pro-max` — дизайн, вёрстка, компоненты, палитры, типографика), сначала прочитай файл `SKILL.md` этого навыка через `view_file` и строго руководствуйся его инструкциями.
- **Установка/Инициализация навыков:** Если для работы требуются локальные навыки, но папка `.gemini/skills/` (или папка настроек AI) отсутствует, пуста или в ней не хватает нужных инструментов, AI обязан самостоятельно определить способ их установки/инициализации и развернуть их перед выполнением основной задачи. Для `ui-ux-pro-max` команда — `npx uipro-cli init --ai gemini` (для Claude Code — `--ai claude`, установка идёт в `.claude/skills/`).
- **Глобальные навыки:** Если в окружении есть подходящий по контексту глобальный
  скилл — использовать его. Проверять по фактическому списку доступных навыков,
  а не по памяти.

## 🌐 Сетевые Запросы (API)

- **Инструментарий:** GET-запросы через `useGetQuery`, мутации (POST, PATCH,
  PUT, DELETE) через `useMutationQuery`. Прямой `axios` или локальные хуки
  запрещены.
- **Кэш:** Мутации обязаны инвалидировать ключи кэша. Ключи хранить строго в
  `enum`/`const` объектах в `shared/config`. Хардкод-строки для ключей
  запрещены.
- **Эндпоинты:** Версионирование (типа `/v1/`) запрещено. URL обязан
  оканчиваться на действие: `/search` (список), `/create` (создание),
  `/update/:id` (апдейт), `/delete/:id` или `/deactivate/:id` (удаление).
  Стандартный REST без явного действия запрещен.

## 📏 Лимиты и Декомпозиция модуля

- **Лимит:** Максимум 200 строк на ЛЮБОЙ файл (Frontend, Backend, Utils).
  Превысил — декомпозируй (хуки, сервисы, утилиты).
- **Структура модуля:** Папка содержит: `index.ts` (экспорт), `ui.tsx` (главный
  компонент), `model.ts` (типы, валидация), `lib.ts/tsx` (утилиты, `columns` для
  таблиц — создавать их внутри компонента запрещено), папка `ui/` для
  подкомпонентов.
- **Декомпозиция UI:** Сложные формы выносить в `ui/renderFields.tsx`,
  избыточный JSX — в `ui/renderJSX.tsx`. Стейты и методы остаются в `ui.tsx` и
  передаются через пропсы (`IProps`).

## 📁 Архитектура FSD (Data Flow)

Передача данных строго сверху вниз: **Pages** 👉 **Widgets** 👉 **Features** 👉
**Features/ui/**

1. **`pages/`**: Только монтирование роута. Бизнес-логика, API-запросы, стили,
   разметка и conditional rendering запрещены. Рендерит один компонент из
   `widgets` или `features`. Без файлов `index/model/lib.ts`.
2. **`widgets/`**: Умные оркестраторы. Хранят главные стейты, стили основных
   оберток (Layout). Все API-запросы (`useGetQuery`/`useMutationQuery`),
   обработка загрузок и ошибок — ТОЛЬКО тут. Передают данные фичам через пропсы.
   Вызывают только главные компоненты фич (внутренние подкомпоненты фич вызывать
   запрещено).
3. **`features/`**: Принимают пропсы от виджетов, выстраивают детальный UI.
   Прямые вызовы API-хуков запрещены (исключение — статические фичи или простые
   страницы без виджетов).
4. **`entities/`**: Переиспользуемые мелкие компоненты (карточки) и серверные
   типы (`model.ts`).
5. **`shared/`**: Инфраструктура без бизнес-логики. Структура: `config/`,
   `hooks/`, `lib/`, `ui/`, `index.ts`, `model.ts`.

## 🖥️ Backend (Bun + Express + TS + PostgreSQL)

- **Архитектура (Service-Driven):** Однонаправленный поток:
  `Request -> routes -> services -> db -> PostgreSQL`.
- **Слой `routes/`:** Прием HTTP, базовая валидация параметров через
  `shared/utils/`, отправка ответа. Бизнес-логика и прямые вызовы БД запрещены.
- **Слой `services/`:** Основная бизнес-логика, оркестрация БД, сложные
  валидации. HTTP-логика и SQL-запросы запрещены.
- **Слой `db/`:** Параметризованные SQL-запросы через `pg.Pool`, маппинг в TS.
  Склеивание строк в SQL и бизнес-логика категорически запрещены.
- **Слой `types/` & `index.ts`:** Интерфейсы сущностей/API и Public API модуля
  (router + типы).
- **Декомпозиция:** При превышении 200 строк разделять роуты/сервисы/дб на файлы
  (например, `employee.routes.ts`, `position.routes.ts`) и собирать в
  `index.ts`.
- **Работа с файлами:** Для загрузки и обработки multipart-файлов на сервере
  используется исключительно `multer`.

## 🚀 Оптимизация и Безопасность

- **Lazy Loading:** Все компоненты страниц в роутинге (`App.tsx`) загружаются
  через `React.lazy()` и оборачиваются в `<Suspense>` со спиннером.
  Скрытые/тяжелые элементы (модалки, вкладки) подгружать так же.
- **Мемоизация:** Применять `React.memo` для тяжелых дочерних компонентов.
  Пропсы-колбэки вниз передавать строго через `useCallback`.
- **Error Boundaries:** Обернуть крупные блоки (Widgets, Pages) для
  предотвращения падения всего приложения.
- **Хардкод:** Магические строки/числа/статусы запрещены. Все константы выносить
  в `model.ts` или `shared/config/`.
- **Безопасность (Backend):** Валидация всех входящих данных. Обязательный RBAC
  на эндпоинтах (`authMiddleware` + `rbacMiddleware`). Защита от SQLi. Секреты
  строго из `.env`. Внутренние детали ошибок клиенту не отдавать (в production
  слать "Внутренняя ошибка сервера"), логировать внутри.
- **Единый `.env`:** Конфиг ОДИН — `.env` в КОРНЕ проекта, общий для сервера и
  клиента. Отдельные `client/.env` и `server/.env` запрещены. Сервер читает его
  через `dotenv.config({ path: <корень>/.env })`, клиент — Bun подхватывает
  `.env` из корня автоматически; в клиентский код попадают только переменные с
  префиксом `APP_*`, серверные секреты в клиент не читать. Переключение dev/prod —
  комментированием соответствующих секций в одном файле. Шаблон — единственный
  `.env.example` в корне; `.env` в `.gitignore`.

## 💎 Эстетика, Качество и Стили (GPUIX)

- **Дизайн-система:** Вся стилизация, выбор цветов, шрифты, отступы, тени и
  спецификации компонентов должны строго соответствовать правилам из
  [DESIGN.md](DESIGN.md). Перед сдачей интерфейса обязательна сверка с разделом
  "Pre-Delivery Checklist".
- **Стили:** В GPUIX нет CSS — единственный способ стилизации это проп
  `style={{}}`. Значения (цвета, отступы, радиусы, размеры шрифта) берутся
  ТОЛЬКО из токенов `shared/config/theme.ts`. Литералы вида `'#1a1a1a'` или
  `padding: 12` прямо в компоненте запрещены.
- **Локальные стили:** Объекты стилей компонента выносятся в `style.ts` внутри
  папки компонента и импортируются в `ui.tsx`. Общие — в `shared/config/theme.ts`.
- **Ограничения GPUIX:** `<text>` обязан получать `color`. Вложенный скролл не
  поддерживается — один скроллер на контейнер. Длинные списки только через
  `<virtual-list>`. Анимации — `motion.div` из `@gpuix/react`.
- **UX/UI правила:**
  - Верстка адаптивная к размеру окна (Flexbox), плавные анимации (`motion`),
    яркие цвета (`vibrant colors`).
  - Действия в списках/таблицах: только иконки без текста (`IconButton` из
    `shared/ui`), обернутые в `<Tooltip>`.
  - Тултипы только через `<Tooltip>` из `shared/ui/Tooltip` (поверх
    `@gpuix/react/tooltip`).
  - Интерактивные элементы (карточки, плашки): эффект сдвига по вертикали при
    ховере запрещен. Реагировать через `hover: {}` изменением цвета фона,
    границ или тени.

## 🔗 Коммуникация и Временные файлы

- **Язык и Запрет Артефактов:** Общение, коммиты — строго на русском. Категорически запрещено создавать, изменять или использовать любые файлы планирования, чек-листов и отчетов (такие как `implementation_plan.md`, `task.md`, `walkthrough.md` и др. в каталоге артефактов), чтобы не тратить токены пользователя, если только пользователь явно об этом не попросит (в этом случае можно создать `implementation_plan.md`). Во всех остальных случаях вносить изменения сразу напрямую в код. Автоматический запуск браузера запрещен без явного одобрения юзера.
- **Временные файлы:** Запрещено оставлять в каталоге проекта скрипты проверки
  БД, заглушки (типа `db-check.ts`). Временные файлы отладки создавать строго в
  `<appDataDir>\brain\<conversation-id>/scratch/` либо полностью удалять перед
  ответом.

- **Сборка проекта:** Запрещено запускать `npm run build` или осуществлять
  принудительную проверку типов после изменений, если только пользователь явно
  об этом не попросит.
